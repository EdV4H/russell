## 決定事項（本ラウンドで確定）

1. **プライバシー方針はパラメータである。** retention・「忘れて」の削除範囲・機微情報ガードを、固定ルールとしてハードコードせず、**temperament / preset と同じく `config_version` で版管理し、`channel_settings` でチャンネル別に上書きできる設定値**として持つ（§6.1 公開版方式）。各実行は開始時に版を pin する。ポリシー変更＝新しい config を公開、ロールバック＝過去版の再公開。plugin-first の思想をポリシー層にも適用する。
2. **チャンネルは opt-in 既定。** Russell は明示的に招待され、かつ管理者が台帳登録したチャンネルのみ購読・記憶する（下記 §4）。「いるチャンネル全部を勝手に読む」は既定禁止。**← 確定。**
3. **決めたのは"機構"、残るのは"デフォルト値のサインオフ"。** 下記の各パラメータ・レベル・カテゴリは実装すべき機構として確定。各パラメータの**初期デフォルト値**は本書のドラフトを叩き台とし、その値への最終承認（特に全公開の是非）のみ人事・法務に残る。

## 0. なぜこの合意が発注前ブロッカーなのか

Russell は同僚の Slack 発言を記憶（メモ帳・本棚・日記）に貯め、しかも **記憶を全公開する**（設計書 §10.1）。日記は毎朝 `#<個体名>-日報` チャンネルへ投稿され、本棚は読み取り専用 Web UI で誰でも閲覧できる。「誰が・いつ・何を言ったか」を要約したものが本人以外の目に触れ続ける——技術ではなく労務・プライバシーの問題。パラメータ化によって「どこまで記憶し・どれだけ保持し・何を書かないか」を運用で調節できるようにするが、**既定値の妥当性は人間が承認する**。

## 1. 従業員データの記憶・要約・日報公開の労務／プライバシー確認

### 方針（デフォルト・要サインオフ）

- Russell が投入されるチャンネルの参加者全員に、投入前に周知する（何を読み・何を書き・何を記憶するか）。周知文面はドッグフーディング設計（[`../dogfooding/plan.md`](../dogfooding/plan.md)）と共通化。
- 記憶・日報公開の対象は **業務上の発言のみ**。DM（`message.im`）はメモ帳の短期文脈には使うが、日記・本棚への昇格対象からは除外（パラメータ `memory.dm_promotable = false` を既定）。
- 日報・本棚に載る記述は「出来事・決定・学び」に限定し、人物評価は載せない（線引きは [`sensitive-info-guard.md`](./sensitive-info-guard.md) のガードパラメータ）。

### チェックリスト

- [ ] Slack 発言を記憶・要約・日報公開することの労務観点確認（人事）
- [ ] 同・プライバシー／個人情報保護観点の確認（法務）
- [ ] 就業規則・プライバシーポリシー・従業員向け同意文の改定要否の判断
- [ ] 投入チャンネル参加者への周知文面の承認

## 2. Retention（保持期間・削除依頼対応手順）— パラメータ化

保持は固定値でなく `config_version` の `retention` ブロックで調節する。下表はデフォルト値のドラフト（値のサインオフのみ残）。

```json
// config_version.retention（例・調節可能）
{
  "raw_log_ttl_days": 90,          // 生Slackログの保持。忘却対象外の一次データ
  "notes_ttl_days": 7,             // メモ帳（§3.1 既定7日）
  "journal_retention_days": null,  // 日記。null=無期限 / 数値で失効（既定案: 397日=13か月）
  "book_decay": "curve",           // 本棚は忘却曲線(§3.4)に委ねる。strength<0.2 で archived
  "archived_hard_delete_days": 730, // 書庫(archived)の物理削除。null=しない（既定案: 24か月）
  "pinned_min_strength": 0.8,      // 「覚えておいて」ピンは長期保持（§3.4）
  "usage_ledger_days": 730,        // 使用量イベント台帳
  "event_log": "append_only"       // 監査ログは削除しない（§3.1）
}
```

- **退職者の扱い（パラメータ `retention.offboard_days`）**: 退職から N 日以内に本人発言由来の記憶を削除または匿名化。N の既定案は要決定。
- **削除依頼の受付窓口**: 管理チャンネル or 指定フォーム経由で受付、承認者（[`../operations/`](../operations/)）が実行。実行は `config_version` と event_log に記録。

### 要サインオフ（デフォルト値の確定）

- [ ] `journal_retention_days` の既定（無期限 vs 13か月案）
- [ ] `archived_hard_delete_days` の既定（無期限保持 vs 24か月案）
- [ ] `offboard_days`（退職者削除・匿名化の期限）
- [ ] 削除依頼の本人確認方法・SLA（何営業日以内）
- [ ] バックアップ（別環境の不変保存 §12-6）と削除権の両立方法（不変バックアップからの削除除外の可否）

## 3. 「忘れて」の削除範囲 — 段階（レベル）をパラメータ化

削除の強さを段階（レベル）として定義し、既定レベルを `config_version` の `forget` ブロックで指定する。自然言語の「忘れて」には既定レベルを適用、管理者は個別にレベル指定・`mode` 切替できる。

| レベル | 実体 | 効果 | 可逆性 |
|---|---|---|---|
| **L1: 弱める** | 対象 book の `strength` を下限まで下げ書庫落ち（`archived`） | 会話の想起パスから外れるがデータは残る・`deep_recall` で到達しうる | 可逆 |
| **L2: 本棚から削除** | 対象 book を物理削除。索引カード・`entity_links` も更新。Finding の evidence 参照を無効化 | 本棚から消える。日記の該当記述は残る | 不可逆（本棚） |
| **L3: 遡及消去** | L2 + 日記 `journal_entries` の該当イベント記述を編集/削除 + 日報チャンネル過去投稿の扱いを規定 | 監査可能性（§12-5 来歴）と緊張。正式な削除依頼(§2)経由のみ | 不可逆 |

```json
// config_version.forget（例・調節可能）
{
  "default_level": "L2",     // 自然言語「忘れて」の既定。L1 / L2 / L3
  "mode": "delete",          // delete=物理削除 / archive=書庫退避（論理削除。監査は残る）
  "hitl_from_level": "L2",   // このレベル以上は実行前に HITL 確認（内容プレビュー+承認）
  "l3_requires_formal_request": true  // L3 は §2 の正式削除依頼手続き経由のみ
}
```

- 既定案は **L2 / mode=delete / L2 以上 HITL / L3 は正式手続きのみ**。「削除権を実際に効かせる」ことを重視しつつ、日記の遡及消去（監査に影響）は正式経路に限定する折衷。
- 「完全に消して」等の明示指示は個別に L3 を指定可能（HITL＋正式手続き）。

### 要サインオフ

- [ ] `default_level` の既定（L1/L2/L3）と `mode`（delete/archive）
- [ ] 日報チャンネルへ投稿済みの過去メッセージを Slack 上でも消すか
- [ ] 削除権（§2）と監査可能性（§12-5）のどちらを優先するかの原則明記

## 4. 参加チャンネルの opt-in / opt-out 方針 — **確定: opt-in 既定**

- **opt-in を既定とする（確定）。** 明示的に招待され、かつ管理者が台帳登録したチャンネルのみ購読・記憶（§10 購読は `app_mention` / `message.im` / 参加チャンネルの `message.channels`）。勝手読みは既定禁止。
- チャンネル追加は管理者操作（`/russell config`、§6.1）で行い event_log に記録。
- **記憶禁止チャンネル（ブロックリスト）**: 人事・給与・health・1on1・経営など、招待されても記憶しない種別を `channel_settings` で定義（[`sensitive-info-guard.md`](./sensitive-info-guard.md) と連動）。
- チャンネル参加者が「このチャンネルでは記憶しないで」と opt-out できる導線（管理者申請）を用意。

### 要確定（機構は確定・運用値のみ）

- [ ] チャンネル追加の承認者・手続き（→ [`../operations/ownership-and-approval.md`](../operations/ownership-and-approval.md) と一致させる）
- [ ] 記憶禁止チャンネル（ブロックリスト）の初期リスト作成

## 5. 実装者への引き継ぎ事項（発注時に渡す確定値）

`config_version` に載る**ポリシーパラメータ一式**を仕様として渡す。実装者裁量ではなく発注側承認事項（[`scope-and-contract.md`](./scope-and-contract.md) の仕分け表）。

- [ ] `retention.*` → 夜間バッチの削除スイープ・書庫スイープ（§4-4）のパラメータ入力
- [ ] `forget.*`（レベル/mode/HITL閾値）→ §3.3/§3.4 の strength 操作 or 削除の実装分岐
- [ ] opt-in 台帳＋ブロックリスト → surface プラグイン（`surface-slack`）の購読フィルタ
- [ ] 機微ガードパラメータ（[`sensitive-info-guard.md`](./sensitive-info-guard.md)）→ 夜間バッチの日記/日報生成フィルタ
- [ ] 削除依頼 API / 手続き → 管理者向け機能

> [!NOTE]
> これらパラメータは §6.1 の公開版方式に載せる。デフォルト値の初期セットが「個体1号の初期 config_version」の一部になる（[`../initial-data/temperament-unit-01.md`](../initial-data/temperament-unit-01.md) と同じ版に同梱）。
