## 0. なぜ2本立てか

「人間らしさ」は性格の演技ではなく記憶の道具と生活リズムの帰結（設計書 §1）。したがって評価も2軸で測る:

1. **記憶想起の抜き打ちテスト（客観・正答率）** — 「昨日の件が通じる」を数値化。§3 の記憶システムが機能しているかの客観指標。[`test-strategy.md`](./test-strategy.md) P1-1 の実測手順を本書が提供する。
2. **週次アンケート（主観・同僚感スコア）** — 「一人の同僚がそこにいる」体験が成立しているかを住人の主観で測る。うざさ ↔ 有能さ（§13 P3）もここで測る。

どちらも単独では不十分。正答率が高くても「うざい／同僚に感じない」なら失敗、逆も同様。

## 1. 記憶想起の抜き打ちテスト（プロトコル・ドラフト）

### 目的

前日以前の出来事・決定・エンティティを Russell が想起できるかを、予告なしの質問で測る。§3.2 の会話読み出し（active）と §3.3 の `deep_recall`（書庫・日記の深掘り）の両方をカバーする。

### 手順

1. **質問生成**: 対象個体が実際に関与した過去の出来事から、テスターが質問を作る。カテゴリを混ぜる:
   - 直近（前日）の出来事 — active 記憶で答えられるべき
   - 1〜2週間前 — 忘却で archived 化しているかもしれない → 「うろ覚えなので書庫を探します」宣言 + `deep_recall`（§3.2）で到達できれば正答扱い
   - エンティティ（人・プロジェクト）に紐づく事実 — 索引カード経由（§3.2）
2. **抜き打ち実施**: 予告なく Slack で mention して質問。**提案: 週 1 回・1回あたり 5〜10 問。**
3. **採点**（提案ルーブリック）:
   - **正**: 事実として正しく答えた（deep_recall 経由の想起も正）
   - **部分**: 方向は合うが detail 欠落 → 0.5 点
   - **誤**: 事実が誤り（ハルシネーション含む）
   - **正直な不知**: 「覚えていない／記録にない」と正しく申告 → **誤ではなく別集計**（§6.3 完全性契約の精神。知ったかぶりより価値がある）
4. **指標**: 正答率 = (正 + 0.5×部分) / 出題数。ハルシネーション率（誤のうち自信を持って断言した割合）を別途記録。

### バー

- [ ] 正答率 ≥ **85%**（[`test-strategy.md`](./test-strategy.md) P1-1 と同一値）
- [ ] ハルシネーション率 ≤ **5%**（知ったかぶりを重罪とする）

- [ ] 質問生成手順・カテゴリ配分の確定
- [ ] 採点ルーブリックの確定
- [ ] 抜き打ち頻度・出題数の確定

## 2. 週次アンケート（項目ドラフト）

### 対象・頻度

投入チャンネルの住人（[`../dogfooding/plan.md`](../dogfooding/plan.md) で選定）に週 1 回。所要 2 分程度。設計書 §13 の「毎フェーズでチーム内ドッグフーディング評価」を定量化する。

### 設問（ドラフト・5件法: 1 全くそう思わない 〜 5 強くそう思う）

**A. 同僚感（残課題2の主観軸）**

- [ ] Q1: 今週、Russell は「同僚がいる」と感じられた
- [ ] Q2: Russell の発言・日報から、以前のやり取りを覚えていると感じた
- [ ] Q3: Russell は自分の得意・不得意をわきまえて振る舞っていた（全能でない人間らしさ、§8.1）
- [ ] Q4: Russell は自分の間違いやつまずきを率直に見せた（§4-2 教訓・§6.4 セルフイシュー）

**B. 有能さ**

- [ ] Q5: 今週、Russell の気づき・提案が実際に役立った
- [ ] Q6: Russell の日報は読む価値があった（[`test-strategy.md`](./test-strategy.md) P1-6）

**C. うざさ ↔ 邪魔さ（§13 P3・P2-4）**

- [ ] Q7（逆転項目）: Russell の自発的な発言はうるさい／邪魔だと感じた
- [ ] Q8（逆転項目）: 朝の投稿や通知の頻度が多すぎると感じた

**D. 信頼・透明性**

- [ ] Q9: Russell が何を記憶し何をできるか（装備・本棚）が見えて安心だった（§9.4・§10.1）
- [ ] Q10（逆転項目）: Russell に自分の発言を記憶・公開されることに不快感があった（→ [`../governance/privacy-and-memory-policy.md`](../governance/privacy-and-memory-policy.md) にフィードバック）

**自由記述**

- [ ] 今週いちばん良かった Russell の振る舞い / 直してほしい振る舞い
- [ ] 「切りたくなった」瞬間があれば（[`../dogfooding/plan.md`](../dogfooding/plan.md) の撤退基準に接続）

### 集計・バー（提案）

- 同僚感（Q1〜Q4 平均） ≥ **3.5 / 5** で当該フェーズ合格の目安
- うざさ（Q7・Q8 の逆転後平均）が **一定以下**（要確定）。§13「うざさ ↔ 有能さ」のバランスを毎週トラッキングし、悪化したら proactivity を下げる（[`dryrun-to-live-promotion.md`](./dryrun-to-live-promotion.md) の rollback / week 単位の引き上げ判断に接続）

- [ ] 設問の最終確定（過不足・逆転項目の扱い）
- [ ] スコアの合格ライン確定

## 3. 残課題3（プリセット追加軸）への接続

設計書 残課題3: ムードメーカー等、業務価値が間接的なタイプを入れるか。本 eval は「業務価値が間接的なタイプ」を測る手段でもある —

- 同僚感（セクション A）が高いが有能さ（B）が中程度でも、チームとして「いてほしい」と評価されるなら価値がある、という判断材料をアンケートが提供する。
- ムードメーカー的プリセットを試す場合、A の重みを上げた別ルーブリックで評価するかを検討する。
