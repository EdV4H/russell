## 積み上げ試算（個体1号・スポンジ・プレースホルダ）

### 1. 対話ターン（§11: ~10k tokens/ターン）

内訳（§11）: システム+人格 1.5k / 記憶注入 3k / スレッド履歴 4k / 応答 2k ≒ **10k tok/ターン**。

| 項目 | 値（仮） | 計算 |
|---|---|---|
| 1ターンあたり | 10k tok（入力8k + 出力2k） | §11 |
| 想定ターン数 | 30 ターン/営業日 | mention 応答中心（P0-P2） |
| 営業日 | 20 日/月 | |
| 月間ターン | 600 ターン | 30 × 20 |
| 月間トークン | 6M tok（入力 4.8M + 出力 1.2M） | 600 × 10k |
| 会話コスト | **≈ $21.6/月**（通常価格 $32.4） | 導入: 4.8M×$2 + 1.2M×$10 |

### 2. 気づきスコアラー（Haiku, §6）

安価フィルタ（LLM なし）を通過したイベントだけ Haiku スコアラーへ。

| 項目 | 値（仮） | 計算 |
|---|---|---|
| スコアラー呼び出し | 200 回/営業日 | フィルタ通過分。実測で調整 |
| 1回あたり | 1k tok | 関連度×緊急度×確信度の判定 |
| 月間 | 4M tok（入力 3.5M + 出力 0.5M 想定） | 200 × 20 × 1k |
| コスト | **≈ $6/月** | 3.5M×$1 + 0.5M×$5 |

### 3. 夜間バッチ（§4, Haiku 中心）

日記・教訓抽出・本棚編集・忘却・関心更新・明日の準備。重い LLM 処理をここに寄せる。

| 項目 | 値（仮） | 計算 |
|---|---|---|
| 1晩あたり | 50k tok | 日記生成 + イベント分節 + 教訓抽出 |
| 実行 | 30 晩/月 | 毎晩 |
| 月間 | 1.5M tok（入力 1.1M + 出力 0.4M 想定） | 50k × 30 |
| コスト | **≈ $3/月** | 1.1M×$1 + 0.4M×$5 |

- プロンプトキャッシュ（システム+人格・記憶注入の固定部分）で入力コストを圧縮できる余地あり。

## 使用量台帳とアラート閾値

§11: `使用量イベント台帳` に LLM/API/送信を**個体付き**で記録 → 個体別コスト＝「人件費」view。

| アラート | 閾値（仮） | アクション |
|---|---|---|
| 日次コスト急騰 | 想定日額の 2倍 | `#ryo-管理` に通知（[`incident-response.md`](./incident-response.md) タイプ3） |
| 月間 80% 到達 | 月額上限の 80% | オーナーに警告 |
| 月間 100% 到達 | 月額上限 | **自動で自発行動を off に落とす**（fail-closed 的、§6.5）。mention 応答は継続するか要判断 |
| 単一個体の突出 | 他個体平均の 3倍 | 暴走/ループ疑い → 調査 |

### 個体別コスト = 人件費 view（§11 観測）

```sql
-- 使用量イベント台帳から個体別の月額を集計（イメージ）
SELECT agent_id,
       date_trunc('month', ts) AS month,
       sum(cost_usd)           AS monthly_cost,   -- "人件費"
       sum(tokens)             AS monthly_tokens
FROM usage_events
GROUP BY agent_id, month
ORDER BY month DESC, monthly_cost DESC;
```

「この個体は月 `$X` 働いて、有用 Finding を Y 件出した」を並べると、[`../dogfooding/plan.md`](../dogfooding/plan.md) の成功指標（費用対効果・切る基準）と接続できる。
