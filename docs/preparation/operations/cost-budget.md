## 使用量台帳とアラート閾値

§11: `使用量イベント台帳` に LLM/API/送信を**個体付き**で記録 → 個体別コスト＝「人件費」view。

| アラート | 閾値（仮） | アクション |
|---|---|---|
| 日次コスト急騰 | 想定日額の 2倍 | `#ryo-管理` に通知（[`incident-response.md`](./incident-response.md) タイプ3） |
| 月間 80% 到達 | 月額上限の 80% | オーナーに警告 |
| 月間 100% 到達 | 月額上限 | **自動で自発行動を off に落とす**（fail-closed 的、§6.5）。mention 応答は継続するか要判断 |
| 単一個体の突出 | 他個体平均の 3倍 | 暴走/ループ疑い → 調査 |

### 個体別コスト = 人件費 view（§11 観測）

```sql
-- 使用量イベント台帳から個体別の月額を集計（イメージ）
SELECT agent_id,
       date_trunc('month', ts) AS month,
       sum(cost_usd)           AS monthly_cost,   -- "人件費"
       sum(tokens)             AS monthly_tokens
FROM usage_events
GROUP BY agent_id, month
ORDER BY month DESC, monthly_cost DESC;
```

「この個体は月 `$X` 働いて、有用 Finding を Y 件出した」を並べると、[`../dogfooding/plan.md`](../dogfooding/plan.md) の成功指標（費用対効果・切る基準）と接続できる。
