# 0001. 会話の文脈は Slack から取り直す（保存しない）

- 状態: 採用
- 日付: 2026-08-10
- 関連: [`../concepts/13-surfaces.md`](../concepts/13-surfaces.md)（スレッド追従）、
  [`../reference/31-core-api.md`](../reference/31-core-api.md)（会話の短期記憶）、
  [`../preparation/governance/privacy-and-memory-policy.md`](../preparation/governance/privacy-and-memory-policy.md)

## 文脈

会話を成立させるために2つの状態を持っていた。どちらもプロセス内のメモリにしかない。

| 状態 | 役割 | 失うと |
|---|---|---|
| 参加スレッド | どのスレッドに入っているか | mention 無しの返信に反応しなくなる |
| 短期記憶 | 直近20発言 | mention しても話の流れを忘れている |

**再起動のたびに両方消える。** 実地で1日に6回再起動し、そのたびに進行中の会話が全部切れた。
本番でもデプロイのたびに同じことが起きる。再起動のたびに記憶を失う同僚は、同僚として成立しない。

当初「P0 ではインメモリで十分」と判断したが、これは誤りだった。再起動は例外的な事象ではなく、
開発でも運用でも日常的に起きる。

## 決定

**会話の文脈は保存せず、必要になった時点で Slack から取り直す。**

知らないスレッドに発言が来たら `conversations.replies` でそのスレッドを取得し、
**Bob の発言が含まれていれば**参加スレッドと判定して、取得した内容をそのまま会話履歴に使う。
DM は `conversations.history` で同じことをする。

コアは Slack を知らないので、`ConversationCapability`（`history(contextId)`）という契約を
services 越しに置き、通信面が実装する。コアは自分の短期記憶が空のときだけこれを呼び、
結果を短期記憶に載せる（2回目以降は取り直さない）。

## 検討した他の案

### A. Postgres に会話を保存する

素直で、Slack 以外の通信面にも効く。**採らなかったのは保持の問題**。

`event_log` は本文を入れない設計（A1-5）、メモ帳は TTL 7日、と決めてきたのに、
会話全文だけが無期限に残ることになる。整合を取るには保持期間・削除要求への対応・
機微情報の扱いをプライバシー方針側で決め直す必要があり、**会話を続けたいだけの変更が
方針変更を要求してしまう**。得るものに対して代償が大きい。

将来 Slack 以外の通信面（Web チャット等）が主になり、そちら側に履歴が無いなら再検討する。

### B. スレッドの発言を来るたびに溜める（保存はしない）

再起動で消えるのは同じなので、問題を解いていない。

### C. 何もしない（mention すれば会話は再開できる）

「毎回 mention すればいい」は運用でそう振る舞ってもらう話であって、設計の答えではない。
そもそも mention しても**流れは忘れている**ので、会話としては回復しない。

## 結果

**良くなること**

- 再起動をまたいで会話が続く。デプロイが会話を切らない
- **Bob の起動前からあるスレッド**でも、mention されれば流れを踏まえて答えられる
- 新しい保存先を作らないので、プライバシー方針を変更せずに済む
- 「記憶は所与のDBではなく、必要なときに構成される道具」という Russell の中心的な見方と噛み合う。
  会話は既に Slack にあるので、二重に持たない

**引き受けること**

- **Slack が唯一の情報源になる。** Slack から消された発言は Bob からも消える（これは正しい挙動だが、
  「Bob だけが覚えている」状態は作れない）
- 知らないスレッドごとに API 呼び出しが1回増える（数百 ms）。一度取ればメモリに載る
- 読むのは招待されたチャンネルのスレッドのみ。**Bob が参加していないスレッドは取得しても捨てる**
  （判定のために一度読む点は、`message.channels` の購読で既に届いているのと同じ範囲）
- 通信面が `ConversationCapability` を実装しない場合（CLI 等）は、従来どおり短期記憶だけで動く

**見直す条件**

Slack 以外の通信面が主になったとき、あるいは「Slack から消えても Bob は覚えている」ことを
求められたとき。後者は保持方針の決定とセットになる。
