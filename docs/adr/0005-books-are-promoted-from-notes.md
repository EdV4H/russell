# 0005. 本はメモから昇格して作る（会話中に直接書かない）

## 文脈

会話中の1往復から `note` と `shelf` を同時に書かせていた（[ADR 0003](./0003-model-decides-what-to-remember.md)）。
実際に動かしたら、**メモ帳と本棚の粒度が同じ**になった。

```
メモ帳:  255字 / 185字 / 232字
本棚:    208字 / 146字 /  63字 / 81字 / 96字
```

内容の書き分け自体は効いていた。メモには「現時点で4サービスに接続されておらず、ヒアリングを
依頼中（返答待ち）」というその時点の状態が入り、本には役割と主要ツールという後々まで効く部分が
残っている。効いていないのは**粒度**の方だった。

原因は材料にある。**同じ1往復を2回要約している**ので、両方が1ターン分の大きさになる。
区別は「時間の射程」のはずが、材料が1ターン分しかないと射程の差が出ようがない。

設計にはもともと別の作り方が書いてある（[`17-habits-and-sleep.md`](../concepts/17-habits-and-sleep.md) §4-3）:

> **本棚の編集** — 週内に3回以上参照されたメモ/スレッドを「本」に昇格（読書カードを書く）

本は**複数のメモを横断して**書かれるから、1件のメモより一段抽象度が上がる。これを実装せず、
会話中に直接書く近道を通したことが、粒度が揃った直接の原因だった。

## 決定

**本は原則、夜間バッチがメモから昇格させて作る。会話中に直接書くのは、明示的に頼まれたときだけ。**

- 会話中の判定は**基本 `note` だけ**を書く。`shelf` が埋まるのは「覚えておいて」と言われた時に限る
- 夜間バッチが、**期間内（既定7日）の未昇格メモ**を読み、繰り返し現れる話題を1冊にまとめる
- **3件以上のメモに現れた話題だけ**を昇格させる（§4-3 の「3回以上」）。ここが粒度の担保
- 昇格した本には来歴を持たせる（`origin='promoted'` / `source_note_ids`）。本棚から会話へ遡れる
- 昇格に使ったメモには `promoted_at` を立てる。翌晩また同じ本が生まれないように
- モデルが返したメモ id は信用せず、渡した候補にあるものだけへ絞る（ADR 0004 と同じ規律, §12-3）
- 昇格は整理より**先**に走らせる。昇格した本も同じ夜のうちに重複判定へ回る
- スキーマ変更は起動時 DDL ではなくマイグレーションで入れる（§11。expand で列追加 → backfill で
  既存の本に `origin='conversation'`）

## 検討した他の案

### A. プロンプトで書き分けを強める（note は期限つき、shelf は一般化）

いちばん安く、すぐ効く。**採らなかったのは、材料の問題を言葉で解こうとしているから**。
1往復しか読んでいないモデルに「一段抽象度を上げて書け」と言っても、書けるのは
その1往復の一般化であって、複数の会話を通して見えてきたことではない。粒度は多少開くが、
「本＝メモの言い換え」という構造は残る。

ただしこれは**併用した**（本 PR で判定プロンプトも直している）。Aは対症療法として悪くない。

### B. 何もしない（会話が増えれば自然に分かれる）

オンボーディングは「これから何をする人か」を決める会話なので、ほぼ全部が長期的に効く事実だった。
通常の業務会話ならメモ側に「17時までに返信」「今日はAさんが休み」が溜まる——という見立ては
正しい。**しかし放っておいても直らない**。原因は会話の内容ではなく、同じ1往復から2つ書かせている
構造の方にあるので。

### C. 参照回数を数えて機械的に昇格させる

「3回以上参照された」を文字どおり実装する案。`recall` のたびにカウンタを増やし、
閾値を超えたメモを本にする。**採らなかったのは、参照回数と重要度が一致しないから**。
同じスレッドで会話が続けば同じメモが何度も読まれるが、それは「その話題が続いている」だけで
「後々まで効く」とは限らない。まとめた本文（複数メモを1〜3文に）も結局モデルにしか書けない。

閾値の意味は「何件のメモに現れたか」に読み替えた。**別々のメモに繰り返し出てくること**の方が、
同じメモが何度読まれたかより、定着の証拠として素直だと考えた。

### D. 昇格させるが、会話中の直接書き込みも残す

保険として両方動かす案。**採らなかったのは、それが今の状態そのものだから**。直接書き込みが
残る限り、本棚は会話粒度の本で埋まり続け、昇格した本がその中に埋もれる。

明示的に頼まれたときだけ直接書くのは残した。「覚えておいて」と言われて一晩待つのは、
同僚として振る舞いがおかしい。

## 結果

- 本棚が「複数の会話を通して見えてきたこと」だけになる。メモ帳との役割が材料の側で分かれる
- 本棚から会話へ遡れるようになった（`source_note_ids`）。「なぜこの本があるのか」が追える
- **本は一晩遅れて載る。** 明示的に頼まれた場合を除き、会話直後には本棚に現れない。
  日中の想起はメモ帳が担う（メモは即時・スレッド単位で効く）ので、会話の質はこれで保たれる想定
- 昇格の質はモデルの出力に依存する。「1回きりの出来事は昇格させない」「メモの言い換えにしない」と
  指示してあるが、外す可能性はある。ADR 0004 と同じく、本棚ビューアと監査で気づける形にしてある
- 既存の本（会話中に直接書かれたもの）はそのまま残る。`origin='conversation'` が付くので、
  後から「昇格で作られた本」と区別して評価できる
- 3件のしきい値は**まだ実測に基づいていない**。会話が溜まってから、昇格が起きなさすぎないか /
  細かすぎる本ができないかを見て調整する必要がある
