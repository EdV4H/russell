# ADR（Architecture Decision Record）

**構造に影響する決定**を、決めた時点の文脈ごと残す。後から「なぜこうなっているのか」を
読み直せるようにするためのもので、結論だけでなく**何を捨てたか**と**何が変わったら見直すか**を書く。

## 何をここに書くか

| | 置き場所 |
|---|---|
| 構造・契約・保存先・外部依存に影響する決定 | **ADR**（このディレクトリ） |
| ある機能の中で閉じる判断・仕様の補足 | 該当ドキュメントの `> [!IMPORTANT] **決定（日付）**` ブロック |

境界は「他の場所の設計を縛るか」。縛るなら ADR。

ADR より前に下した決定は各ドキュメント内の決定ブロックにあり、遡って ADR 化はしていない
（例: [Slack の「AI agent」面を採らない](../concepts/13-surfaces.md)、
[スレッド追従の範囲](../concepts/13-surfaces.md)、
[キルスイッチの凍結粒度](../preparation/operations/kill-switch.md)）。

## 書き方

`NNNN-短い題.md`。連番は作成順で、欠番を作らない。節は4つ:

- **文脈** — 何に困っていたか。決定を読む人が同じ前提に立てるように
- **決定** — 何をするか。断定形で
- **検討した他の案** — なぜそれを採らなかったか。**これが本体**。結論だけの ADR は後で役に立たない
- **結果** — 何が良くなり、何を引き受けたか。副作用と残る課題

状態は `採用` / `置き換え済み（→ NNNN）` / `撤回`。決定を変えるときは元の ADR を編集せず、
新しい ADR を書いて元を `置き換え済み` にする（判断が動いた履歴自体が資産なので）。
