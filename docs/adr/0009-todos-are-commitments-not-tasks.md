# 0009. 引き受けた作業は記憶に持つ（タスク管理ツールにしない）

- 状態: 採用
- 日付: 2026-08-12
- 関連: [`../concepts/12-memory-system.md`](../concepts/12-memory-system.md)、
  [`../concepts/16-findings-and-proactivity.md`](../concepts/16-findings-and-proactivity.md)、
  [`0008-glossary-and-dossiers-are-index-cards.md`](./0008-glossary-and-dossiers-are-index-cards.md)

## 文脈

日報にこう書かれていた。

> 配信単位…頻度…はまだ**回答待ち**。（…）関連文書02も**まだ未読**。登場人物の役割は
> **未確認のまま**。読み進めるかどうかも**判断待ちのまま一日を終えた**。

**個体は未完了を認識している。しかし追う構造が無かった。**

- メモ帳は TTL 7日・スレッド単位。「来週やる」は消える
- 日記は書きっぱなし。読み返す経路が無い
- つまり「やると言ったことをやる」が構造として保証されていない

## 決定

**引き受けた作業を `todos` として持つ。ただしタスク管理ツールにはしない。**

- 記録するのは**個体自身が引き受けたこと**だけ。相手がやることは書かない
- 状態は `open` / `waiting`（相手の返事待ち）/ `done` / `dropped`
- **`dropped` を消さずに残す。** やらないと決めた判断も記録（記憶の扱いと同じ）
- **忘却曲線は適用しない。** 引き受けたことを時間で忘れてはいけない。
  代わりに「何日動いていないか」を出す
- 作るのも閉じるのもモデルが決める（[ADR 0003](./0003-model-decides-what-to-remember.md) の路線）。
  判定には**すでに抱えている作業を見せる**（[#67](https://github.com/EdV4H/russell/pull/67) と同じ手）——
  見せないと同じ作業を作り直し、終わったことにも気づけない
- 想起は**そのスレッド分だけ**。日報には**全部**出す

### 置き場所の境界

| | 置き場所 | 理由 |
|---|---|---|
| 個体が引き受けた作業 | **Russell の DB** | 個体の内部状態。外部ツールへ流すと、人のタスクボードに個体の内部作業が混ざる |
| チームで共有するタスク | **装備**（Notion / GitHub Issues） | 二重管理を作らない。人が普段見る場所に置く |

境界は「**誰が消化するか**」。混ぜると両方が壊れる。

## 検討した他の案

### A. メモ帳（`notes`）に持たせる

新しいテーブルが要らない。**採らなかったのは TTL があるから**。既定7日で消えるので、
「来週やる」が消える。スレッド単位なのも合わない（作業は会話をまたいで残る）。

### B. 索引カード（`entities`）に持たせる

[ADR 0008](./0008-glossary-and-dossiers-are-index-cards.md) で単語帳と個人カルテを乗せた場所。
**採らなかったのは、索引カードが状態を持たない構造だから**。作業は状態（未完了・完了・やらない）と
持ち主と経過時間を持つ。乗せると `entities` が何でも入る箱になり、ADR 0008 で保った
「索引カード」の意味が薄れる。

### C. `findings`（気づき）に統合する

状態機械（`detected` → `acknowledged` → `resolved`）がよく似ている。**採らなかったのは
出自が違うから**。findings は「検知器が外界から気づいたこと」で、作業は「会話で自分が
引き受けたこと」。生成経路も、消し方も、通知の要否も違う。

将来「気づきを引き受けて作業にする」遷移はありうる。そのときは finding → todo の変換であって、
同じテーブルにする話ではない。

### D. 外部のタスク管理ツールに全部置く（装備）

人が普段見る場所に集まるのが利点。**採らなかったのは、個体の内部作業が人のボードを汚すから**。
「02のドキュメントを読む」「用語の意味を確認する」が人のスプリントボードに並ぶのは邪魔でしかない。

逆に、チームで共有すべきタスクを Russell の DB に持つのも間違い（人が見に来ない場所に置くことになる）。
**どちらに置くかは「誰が消化するか」で決める**、というのがこの ADR の結論の半分。

### E. 作らない（日報に「未完了」を書くだけ）

いちばん安い。実際、最初はこれを推した。**採らなかったのは、日報が書きっぱなしだから**。
毎朝出る文章に未完了が並んでも、**次の日に引き継がれない**。構造として残らないと
「先週の約束」が消える。

## 結果

- 「やると言ったことをやる」が構造になった。TTL でも忘却曲線でも消えない
- **止まっていることが見える。** 「N日動いていない」が想起にも日報にも出る
- 日報が「やったこと」だけでなく「**残っていること**」を書くようになった。
  同僚の日報として価値があるのは、むしろそちらだと考えている
- **個体はまだ自分で消化できない。** 自発行動が無いので、作業を持っても人が聞くまで動かない。
  この ADR は自発行動（§6）の**燃料を用意した**段階で、それ自体では完結しない
- 拾いすぎ・拾わなさすぎはモデルの出力に依存する。1ターン5件で頭を打つが、
  「引き受けた」の判定そのものは実測を見て調整が要る
- 機微情報の印が付いた作業は日報に出さない（[ADR 0007](./0007-sensitive-guard-marks-not-blocks.md) と同じ扱い）
